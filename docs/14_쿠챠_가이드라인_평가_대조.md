## 2. 승인 기준(가이드 07) ↔ 앱 검수 항목 대조
가이드의 최종 판정은 "필수 항목 실패는 점수와 관계없이 반려". 앱의 대응은 **차단(수정 필요·확인 필요 중 blocking) = 반려**, **경고 = 추가 검토**로 읽는다.

| 가이드 필수 통과 항목 | 가이드가 보는 것 | 앱 검수에서 대응하는 항목 | 판정 방식 | 결과가 달라질 수 있는 곳 |
|---|---|---|---|---|
| 서비스 정확성 (service_v1, claim_v1) | 가격 비교·경품·투자 수익, 특정 상품 선택·중복 없음·100% 당첨 등 과장 주장 | **금지 표현** (브랜드 '필수' → 수정 필요·차단) | 자동 (문자열 포함 검사) | 표현이 다른 어미·띄어쓰기("백프로 당첨")는 놓친다. 이미지 안의 글자는 검사하지 않음(생성 시 글자 금지로 예방) |
| 교육 맥락 분리 (context_v1) | 서비스 이용 단계·앱 화면·버튼·순서도·멀티패널이 프롬프트·결과물에 0건 | 프롬프트: 입력 단계에서 제외(테스트). **결과 이미지: 검사 항목 없음** | 프롬프트는 자동, 이미지는 없음 | **가장 큰 공백.** 배경 모델이 버튼·화면·화살표를 그려도 앱은 모른다 → 이미지 톤 '확인 필요'(사람)로만 잡힘 |
| 지식재산권 (ip_v1) | 가짜 로고·미승인 캐릭터·상품 모방 | 로고: **로고 비율**(원본 대비 2% 이내)·원본 합성. 캐릭터·상품 모방: 없음 | 로고만 자동 | 생성 배경에 유명 캐릭터가 섞여도 자동으로 못 잡는다 → 사람 확인 |
| 주장 근거 (live_guard_v1) | 가격·확률·배송·혜택은 출처·확인일 있는 값만, 쿠지 준비 중 | 금지 표현에 '쿠지' 포함. 카피 프롬프트 "제공되지 않은 사실은 만들지 않는다" | 부분 자동 | 사용자가 브리프에 넣은 가격·혜택은 출처 없이도 통과한다(앱에 live_claims 구조 없음) |
| 성인 타깃 (audience_v1) | 아동·미성년자 대상 표현, 유아 말투 금지 | **검사 항목 없음**. 어조 설명에 "성인 대상"만 | 없음 | 문구 어조 '확인 필요'(사람)에 의존 |
| 문자 품질 (text_v1) | 깨진 한글·무의미 문자 | 한글 문구는 텍스트 레이어라 깨질 수 없음. 이미지 안 글자는 생성 시 금지 | 구조로 예방 | 배경에 글자가 생기면 앱은 못 잡는다 → 사람 확인 |
| 기록 완전성 (generation_metadata) | 제공사·모델·버전·시드·설정·소요·비용·생성 시각·파일 해시 | 호출 기록(모델·소요·토큰·비용·시각), 프롬프트 전문, 내보내기 manifest 의 sha256 | 자동 | **시드값 없음**(모델이 제공하지 않음), 모델 버전은 모델명으로 대체 |
| 품질 점수 (항목별 4점 이상) | 프롬프트 준수·시각 브랜드 적합성·문체 적합성 | 분석 탭의 Claude 비전 채점(톤 일치·내용 일치·표현 방식·금지 요소·글자/로고 없음, 5점 척도) | 반자동 (LLM) + 사람 | 채점 항목 이름이 가이드와 다르다. 가이드의 "4점 이상"을 그대로 쓰려면 채점 프롬프트 항목을 맞춰야 함 |
| 예상 결과 일치 (expected_status·error_code) | 반려 10건이 정의대로 반려되는가 | **없음** — 위반 테스트셋 미작성 | 없음 | Day 5 미완 항목. 가이드의 반려 10건(필수값 누락·허용값 오류·교육 정보 유출·미승인 IP·미성년자 타깃·근거 없는 주장·만료 정보·쿠지·문자 깨짐·예산 초과)을 테스트 케이스로 옮기면 됨 |

## 3. 제외·금지 사전 ↔ 앱의 대응
| 사전 | 앱에서 자동으로 막는 것 | 사람이 봐야 하는 것 |
|---|---|---|
| service_v1 서비스 오인 | 금지 표현: 가격 비교·경품·투자·수익·디지털 아이템 | 이미지 속 상징(돈·경품 상자) |
| casino_v1 도박 이미지 | 금지 표현: 카지노·잭팟·룰렛·슬롯머신·베팅·코인 | 네온·칩·룰렛 **그림** — 이미지 톤 설명으로 생성은 억제하지만 검수는 사람 |
| claim_v1 과장 주장 | 금지 표현: 최저가·무조건 무료배송·100% 당첨·손해 없음·중복 없음·시크릿 보장·희귀 보장·특정 상품 선택 | 다른 표현의 같은 뜻 |
| audience_v1 아동 타깃 | 없음 | 문구 어조·이미지 톤 |
| ip_v1 지식재산권 | 로고 원본·비율 | 캐릭터·패키지 모방 |
| text_v1 문자 깨짐 | 텍스트 레이어 구조 | 배경에 생긴 글자 |
| quality_v1 저품질 | 없음 (해상도는 규격 '제작 기본값'으로 보장) | 네온·광택·빨강-금색 |
| live_guard_v1 실시간 정보 | 금지 표현 '쿠지' | 가격·확률·혜택 문구의 출처 |
| context_v1 교육 맥락 | 프롬프트 입력 차단 | **결과 이미지** |

**가이드 최종 판정(추정): 추가 검토** — 필수 항목 중 '지식재산권'과 '성인 타깃'이 사람 판단을 요구하고, 캐릭터 생성은 반려 사유가 될 수 있다. 앱 판정은 '5지면 통과 + 차단 2(규격·구조)'로 서로 다르다.

## 5. 결론 — 결과가 다른가
1. **카피·문구 규칙은 같은 결과가 나온다.** 필수 표현 '쿠챠', 금지 표현 21개, 어조는 앱 생성 단계에서 이미 지켜졌고 검수도 통과. 가이드 기준으로도 통과.
2. **이미지에 대한 판정이 다르다.** 앱은 규격(크기·형식·용량·안전영역)과 로고(원본·비율)만 자동으로 보고 나머지는 '이미지 톤 확인 필요' 한 줄로 사람에게 넘긴다. 가이드는 이미지 안의 **피사체(미승인 캐릭터)·분위기(아동 광고 인상)·교육 맥락(UI·순서도)** 을 필수 통과 항목으로 둔다. 이번 결과물은 앱에서 통과했지만 가이드로는 '미승인 캐릭터' 때문에 추가 검토 또는 반려다.
3. **차단 사유의 성격이 다르다.** 앱의 차단 2건(정사각 로고·아이콘 색 확인)은 가이드가 보지 않는 매체 규격·구조 문제. 가이드의 반려 후보(IP·아동 타깃)는 앱이 보지 않는 내용 문제.
4. **비용은 문제가 아니다.** 지면 6개·아이콘 10개가 198원. 가이드가 요구하는 '기록'은 시드값만 빼고 남는다.
