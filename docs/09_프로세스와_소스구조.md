# 09. 프로세스와 소스 구조 (2026-10-19 기준)

브랜드 등록부터 검수·내보내기까지 사용자가 밟는 단계와, 각 단계가 어느 파일에서 처리되는지 정리한다.
(구현 세부와 결정 이력은 docs/01, 검토 항목은 docs/08)

## 1. 사용자 프로세스

```
[브랜드 탭]            [규격·메시지·시안 탭 — 캠페인]                                [편집]      [검수·내보내기]
1 브랜드 규칙 등록  →  2 캠페인 만들기 → ① 규격 선택 → ② 상품·메시지 입력 →  3 편집   →  4 검수 → ZIP
   (로고·색·폰트·톤·       (브랜드 규칙 버전에 연결)     ③ 카피 생성·시안 선택         (지면별)     (지면 + 아이콘 세트)
    필수/금지 표현)                                       ④ 이미지 생성 (+ 아이콘 세트)
```

| 단계 | 사용자가 하는 일 | 서버에서 일어나는 일 | 과금 |
|---|---|---|---|
| 1 브랜드 규칙 | 브랜드명·설명, 로고(투명 PNG/SVG), 허용 색상, 폰트, 아이콘 스타일, 이미지 톤, 어조, 필수/금지 표현, 항목별 필수/권장 등급 | `Brand` + `BrandVersion` 생성. 수정할 때마다 **새 버전**이 생기고 이전 버전은 보존 | 없음 |
| 2 캠페인 | 작업 브랜드 선택 → 캠페인 이름 → ① 지면 선택(공식 확인된 규격만) → ② 상품명·설명·핵심 메시지·타깃·제품 이미지·배경 형태·필수/금지 표현 → "시안 생성하기" | `Design` 생성(만든 시점의 브랜드 버전 id 고정). 시안 생성 = 카피 생성 호출 | 카피 1회 |
| ③ 카피 | 시안 A/B/C 중 하나 선택(모든 지면에 같은 문장) | 선택 지면의 글자 수 제한을 가장 엄격한 값으로 합쳐 1회 생성, 지면마다 저장·검사. `select-variant` 가 전 지면에 선택 적용 | — |
| ④ 이미지 | "모든 지면 이미지 생성" → 썸네일 그리드 → 카드 클릭으로 크게 보기, 다시 합성, 배경 새로 생성(배경 형태 선택), 아이콘 세트 생성 | 비율군(세로형/가로형/정사각)별 배경: 첫 비율군은 프롬프트로 생성, 나머지는 참조 이미지로 같은 장면을 변형. 지면마다 내용 상자 기준 크롭 + 로고·제목 합성. 아이콘은 브랜드 규칙 버전당 한 세트 | 배경 1~3장, 아이콘 10장 |
| 3 편집 | 지면 카드 선택 → 배경 초점/확대, 스크림, 로고(기본 잠금), 제목 글꼴·크기·색·위치 → 저장 / 처음 상태로 되돌리기 / 요소 재생성 | `Element` 행으로 편집, 저장 시 `DesignSnapshot` + 새 합성본. 저장한 지면만 자동 재합성이 막힘 | 재생성만 |
| 4 검수 | "검수 실행" → 지면별 통과/경고/수정 필요/확인 필요, 사람이 '확인함' 체크 → 검수 완료 ZIP 또는 미검수 작업본 ZIP | 규격 조건·문구 제한·브랜드 규칙(색·폰트·로고 비율·필수/금지 표현)·파일 인코딩을 검사해 `ReviewResult` 저장. 차단 항목이 없을 때만 '검수 완료' 내보내기. ZIP 에 지면 폴더·copy.csv·검수결과.csv·manifest.json·아이콘 | 없음 |

규칙의 우선순위: 캠페인 입력(배경 형태, 필수/금지 표현)이 있으면 그것을, 비어 있으면 브랜드 규칙 값을 쓴다(`phrases.effective`).
브랜드 규칙이 새 버전으로 바뀌면 기존 캠페인은 이전 버전 기준으로 남고, 화면에 "브랜드 규칙이 vN 으로 변경됨" 배지가 뜬다.

## 3. 데이터가 흐르는 길 (한 캠페인 기준)

1. `BrandVersion`(규칙) ← 브랜드 탭 저장. 로고·폰트는 `Asset` 파일.
2. `Design`(brand_version_id, preset_version_ids, brief) ← 캠페인 저장.
3. `CopyVariant`(지면별 행, 같은 문장, selected) ← 카피 생성·선택.
4. `GeneratedImage(kind=background)`(비율군별 파일 공유, layout 에 template·style·reference) → `GeneratedImage(kind=composite)`(지면별, layout 에 crop·로고 자리·경고).
5. `Element` + `DesignSnapshot` ← 편집 저장(새 composite 가 쌓임, layout.edited=true).
6. `ReviewResult`(지면 그룹 + 아이콘 그룹 preset None) ← 검수 실행. 바뀐 지면만 무효화.
7. `Export`(ZIP, manifest) ← 내보내기. 최신 composite·선택 카피·아이콘 세트를 담는다.

## 4. 실행·검증
- 서버: backend `uvicorn app.main:app --port 8000`, frontend `npm run dev`(5173). 검증용 8010/5174 설정은 .claude/launch.json.
- 테스트: `REQUIRE_VERIFIED_SPECS=1 backend/.venv/bin/python -m pytest tests -q`, 프론트 타입 `cd frontend && npx tsc -b`.
- 배경 지연 생성: 배경 재생성(시안 화면·편집 화면)은 **사용 중인 지면의 비율군**만 만든다(시안 화면=합성본이 있는 지면, 편집 화면=편집 요소가 있는 지면; 합성본이 하나도 없으면 모든 비율군). 배경 행 layout.scene 이 장면 id 이고(재생성 1회=장면 1개, 참조 변형은 같은 장면), 미룬 비율군은 그 지면을 합성할 때 현재 장면을 참조해 1장 만든다. 현재 장면이 아닌 예전 배경은 재사용·표시하지 않는다. 응답의 deferred 에 미룬 비율군 이름이 온다.
- 배경 품질 2단계: 배경 생성·재생성은 기본이 초안 품질(IMAGE_QUALITY_DRAFT)이고, `POST /designs/{id}/background/regenerate` 에 `final: true` 를 주면 확정 품질(IMAGE_QUALITY)로 만든다. 배경 행 layout.quality·draft 에 남고, 지면 합성이 새 비율군 배경을 만들 때는 시안의 기존 배경 품질을 따른다. 초안 배경이 남아 있으면 검수에 '배경 품질' 경고(차단 아님)가 붙는다.
- 호출 내역: `GET /api/image-usage` 의 calls(오늘 종류별), `GET /api/designs/{id}/api-calls`(시안별 집계·최근 50건). 종류는 background·variant·icon(이미지), copy·icon_names·icon_redraw(채팅). 응답에 종류별 건수·실패·소요·토큰·추정 비용(USD/KRW)이 오고, 프론트 DevStats(카피·이미지·아이콘·편집 화면)가 '개발자 지표' 줄로 보여 준다(누적, 이번 작업 증가분, 내역 표). 호출을 줄일 단계를 고를 때 본다.
- 환경변수(backend/.env): OPENAI_API_KEY, CHAT_MODEL(카피), IMAGE_MODEL·IMAGE_QUALITY(배경 확정 품질·아이콘 기본), IMAGE_QUALITY_DRAFT(배경 초안 품질, 기본 low), IMAGE_DAILY_LIMIT, IMAGE_BG_PER_RATIO·IMAGE_BG_VARIANT·IMAGE_VARIANT_FIDELITY(배경 방식), ICON_RENDER·ICON_IMAGE_QUALITY.
