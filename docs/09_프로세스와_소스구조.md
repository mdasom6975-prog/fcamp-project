# 09. 프로세스와 소스 구조 (2026-10-19 기준)

브랜드 등록부터 검수·내보내기까지 사용자가 밟는 단계와, 각 단계가 어느 파일에서 처리되는지 정리한다.
(구현 세부와 결정 이력은 docs/01, 검토 항목은 docs/08)

## 1. 사용자 프로세스

```
[브랜드 탭]            [규격·메시지·시안 탭 — 캠페인]                                [편집]      [검수·내보내기]
1 브랜드 규칙 등록  →  2 캠페인 만들기 → ① 규격 선택 → ② 상품·메시지 입력 →  3 편집   →  4 검수 → ZIP
   (로고·색·폰트·톤·       (브랜드 규칙 버전에 연결)     ③ 카피 생성·시안 선택         (지면별)     (지면 + 아이콘 세트)
    필수/금지 표현)                                       ④ 이미지 생성 (+ 아이콘 세트)
```

| 단계 | 사용자가 하는 일 | 서버에서 일어나는 일 | 과금 |
|---|---|---|---|
| 1 브랜드 규칙 | 브랜드명·설명, 로고(투명 PNG/SVG), 허용 색상, 폰트, 아이콘 스타일, 이미지 톤, 어조, 필수/금지 표현, 항목별 필수/권장 등급 | `Brand` + `BrandVersion` 생성. 수정할 때마다 **새 버전**이 생기고 이전 버전은 보존 | 없음 |
| 2 캠페인 | 작업 브랜드 선택 → 캠페인 이름 → ① 지면 선택(공식 확인된 규격만) → ② 상품명·설명·핵심 메시지·타깃·제품 이미지·배경 형태·필수/금지 표현 → "시안 생성하기" | `Design` 생성(만든 시점의 브랜드 버전 id 고정). 시안 생성 = 카피 생성 호출 | 카피 1회 |
| ③ 카피 | 시안 A/B/C 중 하나 선택(모든 지면에 같은 문장) | 선택 지면의 글자 수 제한을 가장 엄격한 값으로 합쳐 1회 생성, 지면마다 저장·검사. `select-variant` 가 전 지면에 선택 적용 | — |
| ④ 이미지 | "모든 지면 이미지 생성" → 썸네일 그리드 → 카드 클릭으로 크게 보기, 다시 합성, 배경 새로 생성(배경 형태 선택), 아이콘 세트 생성 | 비율군(세로형/가로형/정사각)별 배경: 첫 비율군은 프롬프트로 생성, 나머지는 참조 이미지로 같은 장면을 변형. 지면마다 내용 상자 기준 크롭 + 로고·제목 합성. 아이콘은 브랜드 규칙 버전당 한 세트 | 배경 1~3장, 아이콘 10장 |
| 3 편집 | 지면 카드 선택 → 배경 초점/확대, 스크림, 로고(기본 잠금), 제목 글꼴·크기·색·위치 → 저장 / 처음 상태로 되돌리기 / 요소 재생성 | `Element` 행으로 편집, 저장 시 `DesignSnapshot` + 새 합성본. 저장한 지면만 자동 재합성이 막힘 | 재생성만 |
| 4 검수 | "검수 실행" → 지면별 통과/경고/수정 필요/확인 필요, 사람이 '확인함' 체크 → 검수 완료 ZIP 또는 미검수 작업본 ZIP | 규격 조건·문구 제한·브랜드 규칙(색·폰트·로고 비율·필수/금지 표현)·파일 인코딩을 검사해 `ReviewResult` 저장. 차단 항목이 없을 때만 '검수 완료' 내보내기. ZIP 에 지면 폴더·copy.csv·검수결과.csv·manifest.json·아이콘 | 없음 |

규칙의 우선순위: 캠페인 입력(배경 형태, 필수/금지 표현)이 있으면 그것을, 비어 있으면 브랜드 규칙 값을 쓴다(`phrases.effective`).
브랜드 규칙이 새 버전으로 바뀌면 기존 캠페인은 이전 버전 기준으로 남고, 화면에 "브랜드 규칙이 vN 으로 변경됨" 배지가 뜬다.

## 3. 데이터가 흐르는 길 (한 캠페인 기준)

1. `BrandVersion`(규칙) ← 브랜드 탭 저장. 로고·폰트는 `Asset` 파일.
2. `Design`(brand_version_id, preset_version_ids, brief) ← 캠페인 저장.
3. `CopyVariant`(지면별 행, 같은 문장, selected) ← 카피 생성·선택.
4. `GeneratedImage(kind=background)`(비율군별 파일 공유, layout 에 template·style·reference) → `GeneratedImage(kind=composite)`(지면별, layout 에 crop·로고 자리·경고).
5. `Element` + `DesignSnapshot` ← 편집 저장(새 composite 가 쌓임, layout.edited=true).
6. `ReviewResult`(지면 그룹 + 아이콘 그룹 preset None) ← 검수 실행. 바뀐 지면만 무효화.
7. `Export`(ZIP, manifest) ← 내보내기. 최신 composite·선택 카피·아이콘 세트를 담는다.

## 4. 실행·검증
- 서버: backend `uvicorn app.main:app --port 8000`, frontend `npm run dev`(5173). 검증용 8010/5174 설정은 .claude/launch.json.
- 테스트: `REQUIRE_VERIFIED_SPECS=1 backend/.venv/bin/python -m pytest tests -q`, 프론트 타입 `cd frontend && npx tsc -b`.

- 아이콘 기능명 후보: 카피 생성 호출이 같은 응답으로 기능명 후보 15개(icons: name·concept)를 돌려주고 브리프 icon_candidates 에 둔다. 3D 아이콘 세트 생성은 후보가 10개 이상 남으면(금지 표현 제외) 기능명 제안 채팅 호출 없이 그것을 렌더하고, 모자라면 전처럼 제안한다. 제안 호출도 15개(ICON_CANDIDATES)를 한 번에 받아 부족분 추가 요청을 거의 없앤다.
- 단색 여백 최소화(프롬프트 1.4): 문구 자리를 '매끈한 단색 면'이 아니라 같은 장면이 초점이 흐려진 채 이어지는 면으로 지시하고, 피사체 비중을 늘렸다(세로 70/30, 정사각 75/25, 가로 65/35, 크롭공용은 피사체 중앙 50%). 가독성은 합성 스크림이 맡는다.
- 생성 설정(시안별, 브리프 image_model·bg_mode, `GET /api/image-settings`·`PUT /designs/{id}/image-settings`): 이미지 모델은 IMAGE_MODELS(쉼표 목록, 없으면 gpt-image-1·1.5·2.5-flare 기본 후보, 기본 모델은 항상 포함)에서 고르고 호출·layout.model 에 남아 DevStats 로 비용·품질을 비교한다. 배경 방식 per_ratio(비율군마다 1장, 변형은 images.edit) / single(1장을 모든 지면이 잘라 씀: imagegen.best_single_template 이 가장 많이 잘리는 지면의 손실이 최소인 비율군을 고르고, 구도는 prompts/image/composition/크롭공용.md, images.edit 호출 없음). 기본은 IMAGE_BG_PER_RATIO(1=per_ratio, 0=single). 
- 배경 지연 생성: 배경 재생성(시안 화면·편집 화면)은 **사용 중인 지면의 비율군**만 만든다(시안 화면=합성본이 있는 지면, 편집 화면=편집 요소가 있는 지면; 합성본이 하나도 없으면 모든 비율군). 배경 행 layout.scene 이 장면 id 이고(재생성 1회=장면 1개, 참조 변형은 같은 장면), 미룬 비율군은 그 지면을 합성할 때 현재 장면을 참조해 1장 만든다. 현재 장면이 아닌 예전 배경은 재사용·표시하지 않는다. 응답의 deferred 에 미룬 비율군 이름이 온다.
- 투명 누끼 지면별 다시 붙이기: 누끼를 코드로 붙인 배경(layout.product_mode composite, clean_file·product_placed)은 붙인 채로 자르면 같은 비율군이라도 지면 비율(예: 가로형 배경 → PMax 1.91:1)에 따라 제품이 잘린다. 지면 합성(완성형·분리 자산형·띠 배너)은 compose.crop_scene 이 크롭 위치는 누끼를 붙인 배경으로 정하고, 누끼 없는 원본(clean_file)을 잘라 그 위에 누끼를 다시 붙인다. 누끼가 지면 밖으로 넘치면 비율을 지켜 줄이고 바닥·가로 중심을 지킨다(fit_product_box, 가장자리 여백 짧은 변의 2%). 합성 보고서 product_fit {box, scale, note}. 누끼 자리는 문구가 피하는 내용 상자에 더한다. 편집 화면(editing.render)은 아직 붙인 배경을 그대로 쓴다
- 레이아웃(캠페인 입력 brief.layout, 기본 '기본'): `backend/app/layouts.json` 의 레이아웃 중 하나(기본·상단 문구·중앙 정렬·좌우 반전). `GET /api/image-settings` 의 layouts 가 이름·설명·비율군별 문구 자리·정렬·제품 구역을 주고, 화면(LayoutPicker)은 그 값으로 배치 그림을 그린다. 배경 프롬프트 구도(imagegen.composition_vars)·제품 구역(product_box)·크롭·합성 문구 자리가 같은 레이아웃을 따른다(routers_images.layout_name). 배경 행과 합성 보고서에 layout {name, version} 을 남기고, 배경의 레이아웃과 지금 레이아웃이 다르면 합성 경고로 '배경을 새로 생성하세요'를 띄운다. 1장 방식(single)은 구도가 크롭공용이라 레이아웃이 합성·크롭·제품 구역에만 반영된다.
- 배경 품질은 한 가지: 배경 생성·재생성은 항상 IMAGE_QUALITY(기본 medium)로 만든다(초안/확정 구분·'확정 품질로 배경 생성'·IMAGE_PROVIDER_DRAFT·IMAGE_QUALITY_DRAFT 제거). 배경 행 layout.quality 에 품질이 남는다. 배경 재생성 뒤 편집 화면에서 저장한 지면은 routers_edit.rerender_edited 가 편집 요소를 유지한 채 새 배경으로 다시 그린다(응답 applied/skipped).
- 제품 누끼 참조: 캠페인 입력의 제품 이미지(투명 PNG)가 있으면 배경 생성을 모두 images.edit 로 보내 누끼를 참조 이미지로 붙인다(첫 비율군은 [제품], 나머지 비율군은 [배경, 제품]). 프롬프트는 prompts/image/product_ref.md 가 background 프롬프트 앞에 붙고 '상품을 장면의 주 피사체로, 모양·색·글자는 그대로, 바닥·조명·그림자만 새로'를 지시한다. layout.product_asset_id 에 남고 호출 종류는 product(비율군 변형은 variant). 공급자가 cloudflare 면 누끼는 쓰지 않는다. 선택한 카피는 배경 프롬프트에 넣지 않는다(카피를 바꿔도 배경은 다시 만들지 않음).
- 검수 후 잠금: 디자인 status 가 '검수 완료'(검수 실행에서 차단 항목이 없을 때 자동 설정)이면 캠페인 입력 수정(PATCH /designs/{id})·배경 재생성·지면 이미지 생성·생성 설정 변경·편집 저장/되돌리기/공통 문구·시안 일괄 적용이 409 이다(routers_review.ensure_unlocked). 입력 값 조회는 가능. `reset-generated`(시안 이미지 초기화)는 미검수로 되돌리므로 잠금 해제 경로다.
- 이미지 비용: OpenAI gpt-image 계열은 장당이 아니라 토큰(텍스트 입력 $5·이미지 입력 $8·이미지 출력 $30 / 100만 토큰, 2.5 기준)으로 과금된다. images.generate/edit 응답의 usage 를 calllog.note_image_usage 가 기록(tokens_in·tokens_out·tokens_text_in·tokens_image_in)하고 pricing.cost_of 가 image_tokens 표로 계산한다. 단가 수정은 data/pricing.json 의 image_tokens 키(모델명 → text_in·image_in·image_out).
- 호출 내역: `GET /api/image-usage` 의 calls(오늘 종류별), `GET /api/designs/{id}/api-calls`(시안별 집계·최근 50건). 종류는 background·variant·product·icon(이미지), copy·icon_names·icon_redraw(채팅). 응답에 종류별 건수·실패·소요·토큰·비용(USD/KRW, 토큰 기록이 없거나 요금표에 없는 호출만 추정 표시)이 오고, 프론트 DevStats(카피·이미지·아이콘·편집 화면)가 '개발자 지표' 줄로 보여 준다(누적, 이번 작업 증가분, 내역 표). 호출을 줄일 단계를 고를 때 본다.
- 환경변수(backend/.env): OPENAI_API_KEY(이미지 생성·openai 채팅), ANTHROPIC_API_KEY·CHAT_PROVIDER(anthropic 기본|openai)·CLAUDE_MODEL(기본 claude-sonnet-5-5)·CLAUDE_EFFORT(기본 low)·CLAUDE_MAX_TOKENS, CHAT_MODEL(openai 채팅), IMAGE_MODEL·IMAGE_QUALITY(배경 품질·아이콘 기본, 기본 medium), IMAGE_DAILY_LIMIT, IMAGE_BG_PER_RATIO·IMAGE_BG_VARIANT·IMAGE_VARIANT_FIDELITY(배경 방식), ICON_RENDER·ICON_IMAGE_QUALITY·ICON_GRID, IMAGE_MODELS(모델 후보), COPY_AUTO_RETRY, COPY_AGENT(0 이면 6단계 "고쳐 보기" 끔), NAVER_CLIENT_ID·NAVER_CLIENT_SECRET(트렌드 수집, NAVER API HUB 애플리케이션의 Client ID/Secret — Search Trend·Shopping Insight 구독; 옛 개발자센터 키면 NAVER_API=developers), NAVER_API(비우면 시크릿 길이로 판별).
- 분석 탭(학습·개발용, 검수와 별개, 2026-10-20): 캠페인을 고르면 `GET /api/designs/{id}/analysis` 하나로 ① 입력↔결과(브랜드 규칙·캠페인 입력이 카피/배경/아이콘 프롬프트·합성 코드·검수 중 어디에 들어가는지 표 — 허용 색상·폰트는 배경 프롬프트에 들어가지 않고, 이미지 톤 설명만 들어간다 —, 배경·아이콘 주요 색 6개와 브랜드 색의 ΔE(CIE76, 20 이하를 '가깝다'), 지면 합성본·카피), ② 보낸 프롬프트 전문(출처 표시: recorded=호출 기록 `data/prompt_log/`, stored=배경·아이콘 행의 prompt, reconstructed=기록·DB 둘 다 없는 채팅을 현재 규칙·입력으로 다시 조립 — 보낸 당시와 다를 수 있음; 입력에서 온 값은 노란 표시), ③ 비용(카피/배경/아이콘/채점 단계 집계 + 호출 내역 전체)을 보여 준다. 'Claude 비전 채점' 버튼은 배경 1장을 Claude 에 보여 주고 톤·내용·표현 방식·금지 요소·글자 항목을 1~5점으로 받는다(채팅 1회 과금, kind judge, prompts/analysis/judge_*.md, 결과는 `data/analysis/judge_<design>.jsonl`). 사람 평가를 대신하지 않는 참고값이며 검수 결과와 무관하다.
