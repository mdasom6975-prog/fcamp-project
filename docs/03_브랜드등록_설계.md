# 03. 브랜드 아이덴티티 등록·적용 설계 (프로젝트 1 필수 ①)

## 전제
- 개발 중에는 **사용자가 가상 브랜드 정보를 직접 입력**한다. (쿠챠 가이드는 개발 완료 후 검수용 입력 데이터)
- 브랜드를 수정하면 기존 버전을 덮어쓰지 않고 **새 BrandVersion** 을 만든다. 기존 승인본은 보존한다.
- 로고는 원본 비율을 보존하고 AI 가 임의로 재생성하지 않는다.

## 확정된 결정
| 항목 | 결정 |
|---|---|
| 규칙 구분 | 항목별 기본값을 두고 사용자가 바꿀 수 있게 (필수 / 권장 / 수정가능) |
| 로고 형식 | PNG(투명) · SVG |
| 폰트 | 제공 목록에서 선택 + 폰트 파일(TTF/OTF) 업로드 둘 다 지원 |
| 이미지 톤·어조 | 설명 텍스트 + 기준 자료(이미지·예시 문구) 업로드 |
| 구분 기본값 | 로고·색상·폰트·필수 표현·금지 표현 = 필수 / 아이콘 스타일·이미지 톤·문구 어조 = 권장 |
| 제공 폰트 | Pretendard (목록 1종 + 파일 업로드) |
| 로고 여백 단위 | 로고 크기 대비 % |
| 색상 역할 | 기본 목록(주조색 · 보조색 · 강조색 · 배경색 · 텍스트색) + 사용자가 역할 이름을 직접 작성하고 색상 코드를 선택해 추가 |

## 입력 항목 (RFP: 브랜드명, 로고, 색상, 폰트, 아이콘 스타일, 이미지 톤, 문구 어조, 필수/금지 표현)
| # | 항목 | 입력 방식 | 검증 | 저장 위치 |
|---|---|---|---|---|
| 1 | 브랜드명 | 텍스트 | 필수 입력, 100자 이내 | Brand.name |
| 2 | 로고 | 파일 업로드(PNG 투명 / SVG) + 여백 + 합성 자리(좌상단 기본·우상단·좌하단·우하단·자동) | 형식 검사, 원본 가로세로 비율 기록. 자리는 캠페인의 모든 지면에 동일 적용 | Asset(kind=logo), BrandVersion.logo_asset_id / logo_margin / logo_position |
| 3 | 색상 | 이름 + HEX + 역할(주조색·보조색·강조·배경·텍스트 등) 여러 개 | HEX 형식 | BrandVersion.colors |
| 4 | 폰트 | 역할(제목·본문 등)별로 목록 선택 또는 TTF/OTF 업로드 | 파일 형식, 한글 글리프 포함 여부 | BrandVersion.fonts, Asset |
| 5 | 아이콘 스타일 | 선 굵기, 모서리(각진/둥근), 채움 여부 | 숫자 범위 | BrandVersion.icon_style |
| 6 | 이미지 톤 | 설명 텍스트 + 기준 이미지 업로드 | 이미지 형식 | BrandVersion.image_tone {description, reference_asset_ids} |
| 7 | 문구 어조 | 설명 텍스트 + 헤드라인 권장 길이 + 존댓말 | 텍스트·숫자·체크 | BrandVersion.voice {description, headline_max_chars, polite} |
| 8 | 필수 표현 | 문구 목록 | 중복 제거 | BrandVersion.required_phrases |
| 9 | 금지 표현 | 문구 목록 | 필수 표현과 겹치면 경고 | BrandVersion.forbidden_phrases |

각 항목은 구분값(필수 / 권장 / 수정가능)을 가진다.
- 필수: 위반 시 검수 완료 차단 대상
- 권장: 위반 시 경고
- 수정가능: 사용자가 편집 화면에서 바꿔도 되는 요소
- 색상·폰트 검사는 편집 가능한 텍스트·도형·아이콘 요소에만 적용하고 사진 전체 픽셀에는 강제하지 않는다 (RFP).
- 이미지 톤·어조는 자동 판정하지 않고 기준 자료와 사람 평가로 확인한다 (RFP).

## 화면 흐름
1. 브랜드 목록 → 새 브랜드 등록
2. 입력 폼 (위 9개 항목, 항목별 구분값 선택)
3. 저장 → BrandVersion 1 생성
4. 수정 → 변경 내용 확인 → 새 버전 생성 (기존 버전 보존)

## 브랜드 적용 방식 (이후 단계에서 사용)
- 생성: 색상·폰트·아이콘 스타일·이미지 톤·어조·필수/금지 표현을 생성 요청의 조건으로 전달
- 로고: 이미지 생성과 분리해 원본 파일을 합성 (변형 금지)
- 편집·검수: 시안은 사용한 BrandVersion 에 연결. 새 버전 생성 시 영향받는 시안을 표시

## 미확정
1. Pretendard 폰트 파일 확보 방법 (공식 배포처에서 다운로드, 사용자 허가 후 진행)

## 구현 현황 (4단계)
- 백엔드: `POST/GET/PUT /api/brands`, `POST /api/assets`, `GET /api/fonts/provided`, `GET /api/brand-defaults`
- 프론트: 브랜드 목록 · 등록/수정 폼 · 버전 선택
- 검증 완료: 불투명 PNG·JPG 로고 거절, 한글 글리프 없는 폰트 거절, HEX 형식, 구분값, 수정 시 새 버전 생성과 이전 버전 보존, 필수/금지 표현 중복 경고
- 아직 없음: 브랜드 삭제, 영향받는 시안 표시(시안 생성 이후 단계), 여백 값의 실제 적용(합성 단계)
