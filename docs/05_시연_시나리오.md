# 05. 시연 시나리오 (Day 1 산출물)

> 10/29 최종 발표에서 보여 줄 7단계 흐름. **시연 시나리오가 곧 개발 순서**다. 각 단계는 앱의 어떤 화면·API에 대응하는지 함께 적는다.

## 시연 데이터
| 항목 | 값 |
|---|---|
| 기준 브랜드 | 쿠챠 (`brands/kucha/brand.json`) |
| 교차 테스트 브랜드 | 시연 직전에 앱에서 직접 입력한다(프로젝트에는 더미 브랜드를 두지 않는다) |
| 브리프 | 상품: 무상표 캡슐토이 신규 컬렉션 · 핵심 메시지: 새로운 굿즈 발견의 즐거움 · 타깃: 만 19세 이상 수집가 |
| 지면 6개 | Meta Instagram 피드 4:5 · Instagram 스토리 9:16 · Facebook 피드 4:5 · 카카오 디스플레이 네이티브 2:1 · 카카오 디스플레이 네이티브 1:1 · Google PMax 가로 1.91:1 |
| 일부러 위반하는 시안 | 금지 표현 "100% 당첨"을 헤드라인에 넣은 시안 → 검수에서 '수정 필요'로 막히는 장면 |

## 7단계
| 단계 | 화면 | 보여 줄 것 | 확인 포인트 |
|---|---|---|---|
| 1 브랜드 등록 | 브랜드 탭 | 쿠챠 로고·허용 색상 6개·폰트·아이콘 스타일·어조·필수/금지 표현 입력, 항목마다 필수/권장 등급 | 저장 후 버전 1 생성. 수정하면 버전 2가 생기고 1은 보존 |
| 2 지면 선택 | 규격 라이브러리 → 규격·메시지·시안 탭 | 플랫폼 > 광고 유형 > 지면 트리에서 6개 선택. 네이버는 '확인 필요 · 검수 불가'로만 보임 | 조건마다 강제/권장/미표기와 출처 URL·확인일 표시 |
| 3 메시지 입력 | 규격·메시지·시안 탭 | 상품명·설명·핵심 메시지·타깃·제품 이미지 입력 → 시안 생성 | 시안에 브랜드 버전·규격 버전이 함께 기록됨 |
| 4 생성 | 시안 화면 | 지면별 카피 3안 → 선택 → 배경 생성 → 로고·제목 합성. 브랜드 3D 아이콘 세트 10개(투명 PNG) 생성, 하나 다시 그리기 | 로고는 원본 비율, 한글 문구는 텍스트 레이어 |
| 5 편집 | 편집 패널 | 로고 잠금 확인 → 배경만 재생성 → 헤드라인을 공통 수정 → 스토리만 지면별 수정 | 잠긴 로고는 글자 하나·위치까지 그대로. 편집하면 검수 결과 초기화 |
| 6 검수 | 검수 패널 | 지면별 통과/경고/수정 필요/확인 필요. 금지 표현 시안이 '수정 필요'로 막히는 장면. 확인 필요 항목을 사람이 '확인함' | 차단 항목이 남으면 '검수 완료 ZIP' 버튼 비활성 |
| 7 다운로드 | 내보내기 | 검수 완료 ZIP 다운로드 → 압축 풀어 지면별 폴더·copy.csv·검수결과.csv·manifest.json 확인 | manifest의 파일 목록·sha256이 실제 파일과 일치 |

추가 시연(RFP 최종 시연 항목): 다른 브랜드(직접 입력)로 같은 브리프를 만들어 색·표현이 섞이지 않는지(교차 테스트), 쿠챠 브랜드를 v2로 바꾼 뒤 기존 시안에 '브랜드 버전 변경' 경고가 뜨고 재검수되는지(버전 변경).

## 최종 결과 세트
```
results/
├─ brand/            쿠챠 brand.json (v1) + 로고 원본 + 해시
├─ icons/            3D 아이콘 10개 (png 256 + src 1024 투명 원본) + 아이콘 검수 결과
├─ designs/          선정 시안 1개의 6개 지면 결과
│   ├─ Meta_Instagram 피드/image.png · copy.txt
│   ├─ Meta_Instagram 스토리/…
│   ├─ Meta_Facebook 피드/…
│   ├─ 카카오_디스플레이 네이티브 2:1/…
│   ├─ 카카오_디스플레이 네이티브 1:1/…
│   └─ Google Ads_PMax 가로 1.91:1/image.png · logo.png · copy.txt
├─ copy.csv · 검수결과.csv · manifest.json
└─ report/           평가 보고서 (지면별 통과율 · 위반 유형 · 생성 시간·비용)
```

## 발표 흐름 (Day 13 기준)
문제(단순 리사이즈의 한계) → 설계(브랜드 버전·규격 버전·요소 목록) → 구현(7단계) → 검수 결과(결과 세트 통과율·위반 검출) → 모델 비교 → 배운 점.
