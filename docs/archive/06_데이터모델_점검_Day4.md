## 1. 시안 원본 형식 — "요소들의 목록"으로 저장하는가
워크북 TIP: 시안을 이미지 한 장으로 저장하면 잠금·부분 수정·검수가 모두 불가능하다. 앱은 다음 세 층으로 나눠 저장한다.

| 층 | 테이블 | 내용 | 키트 design.json 대응 |
|---|---|---|---|
| 시안(캠페인) | `designs` | brand_id, **brand_version_id**, preset_version_ids[], brief, kind, status | design 루트 (brand_version, spec_versions, brief) |
| 지면별 결과 | `generated_images`(kind=composite) | 파일 경로, 크기, prompt, copy_variant_id, **brand_version_id**, `layout` JSON | variants[] |
| 요소 | `generated_images.layout.elements[]` (자동 배치) → 편집하면 `elements` 행 (type, scope, props, z_index, **locked**) | 로고 box·locked, 제목 text·box·font_size·color, 배경 zoom/cx/cy, 스크림 색·투명도 | elements[] (type, position, locked, copy) |
| 저장 시점 | `design_snapshots` | 편집 저장마다 elements 전체 | history |
| 내보낸 파일 | `exports` | files[](path, bytes, sha256), review_summary, zip_path, **brand_version_id**, preset_version_ids | exported files + manifest |

요소 하나의 실제 모양(`generated_images.layout` 에서 발췌):
```json
{
  "template": "세로형", "canvas": [1440, 1800], "content_box": [86, 86, 1354, 1714],
  "elements": [
    {"type": "logo", "box": [86, 86, 338, 338], "locked": true, "note": "원본 비율 유지"},
    {"type": "text", "role": "제목", "text": "오늘 필요한 식재료, 첫 구매 혜택으로", "lines": ["…"],
     "box": [86, 1480, 1354, 1714], "font_size": 108, "color": "#FFFFFF", "color_fallback": true, "fits": true}
  ],
  "scrim": {"mode": "세로형", "color": "#000000", "opacity": 0.62},
  "warnings": []
}
```
편집 후에는 같은 구조가 `elements` 테이블(지면별 행, `locked`, `scope=공통|지면별`, `props.text_override`)로 옮겨지고, 저장할 때마다 새 composite 가 `layout.edited=true` 로 쌓인다.

**키트 스키마와의 차이(기록):** brand-qa-starter-kit 의 `design.schema.json` 은 이 저장소에 없어 필드명을 1:1로 맞추지는 못했다. Day 5 "앱의 시안을 design.json 형식으로 바꾸는 변환 함수"를 만들 때 위 표의 대응을 기준으로 `to_design_json(design_id)` 를 작성한다.

## 2. 자가진단
### Q1. 브랜드를 v1.2로 바꾸면 영향받는 시안을 찾을 수 있는 구조인가? — **예**
- `designs.brand_version_id` 는 시안을 만든 시점의 버전을 가리키고, `brands.current_version_id` 는 최신 버전을 가리킨다. 둘이 다르면 `routers_designs._out()` 이 `brand_outdated=true` 를 돌려주고, 검수(`routers_review.run_review`)는 "브랜드 버전" 항목을 **경고**로 남긴다.
- 브랜드 수정은 항상 새 `brand_versions` 행을 만든다(`PUT /api/brands/{id}`). 이전 버전과 그 버전으로 만든 시안·내보내기(`exports.brand_version_id`)는 보존된다.
- 찾는 쿼리: `SELECT id FROM designs WHERE brand_id=? AND brand_version_id<>(SELECT current_version_id FROM brands WHERE id=?)`.
- 아직 없음: 영향받는 시안을 **목록 화면에서 한 번에** 보여 주는 UI (시안 단건에만 표시). Day 12 "브랜드 버전 변경 시나리오"에서 보강.

### Q2. 화면에 보이는 시안과 실제로 내보낼 파일이 같은 원본에서 나오는가? — **예**
- 미리보기: `GET /api/images/...` 가 최신 composite 파일을 그대로 보여 준다.
- 검수: `review.review_preset()` 이 **같은 composite 파일**을 열어 크기·비율을 재고, `exporting.encode()` 로 실제 인코딩해 형식·용량을 판정한다.
- 내보내기: `exporter.ad_preset_folder()` 가 같은 파일을 같은 `encode()` 로 인코딩해 ZIP에 넣고, manifest 의 파일 목록은 실제로 쓴 바이트에서 sha256 을 만든다.
- 따라서 미리보기 = 검수 대상 = ZIP 파일. 편집하면 `invalidate_reviews()` 가 검수 결과를 무효화해 "편집 후 재검수 없이 검수 완료 ZIP" 경로를 막는다.

### Q3. 브랜드를 2개 이상 저장할 수 있는가? — **예 (10/15 확인)**
`tools/register_brand.py` 로 `brands/kucha/brand.json`, `brands/malkkeum/brand.json` 을 등록해 DB 에 브랜드 3개(마켓컬리·쿠챠·말끔)가 있다. 시안은 `brand_id` 로 분리되고, 작업 브랜드는 화면 상단에서 전환한다. 브랜드 간 자산 격리(다브랜드 Workspace)는 PJ2 범위.

## 3. 버전 추적 경로 (시안마다 브랜드 버전·규격 버전이 기록되는가)
```
Design.brand_version_id ─┐
Design.preset_version_ids ├─→ CopyVariant.preset_version_id → GeneratedImage.brand_version_id / preset_version_id
                          └─→ ReviewResult.preset_version_id → Export.brand_version_id / preset_version_ids
PresetVersion.version_no · source_urls · checked_at · status ─→ manifest.json (spec_version_no, spec_checked_at, spec_sources)
```
규격이 바뀌면 `preset_versions` 에 새 version_no 행을 추가하고 이전 행은 `active=false` 로 둔다(삭제하지 않음). 기존 시안은 이전 `preset_version_id` 를 그대로 가리키므로 "어느 규격 버전 기준인지" 추적된다. 규격 원문 변경 감지는 `routers_spec_update.py`(해시 비교, 자동 덮어쓰기 없음).
