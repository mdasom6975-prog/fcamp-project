# 12. 로드맵 (v0.9.0 → v1.0.0)

> 초안 — 2026-10-22, 기준 커밋 `v0.9.0`. 항목·우선순위는 작업하면서 이 문서에서 고친다(이슈를 만들기 전의 원본).
> 변경 이력은 `CHANGELOG.md`, 브랜치·커밋·릴리스 규칙은 `docs/13_개발_규칙.md`.

## 1. 목표: v1.0.0 의 정의

**처음 접속한 사람이 안내 없이 브랜드 등록부터 내보내기까지 막힘 없이 시연할 수 있고,
배포 링크·README·스크린샷이 갖춰져 포트폴리오로 바로 보여 줄 수 있는 상태.**

v1.0 은 아래 네 조건을 모두 만족해야 한다.

| # | 조건 | 판단 방법 |
|---|---|---|
| 1 | **끝까지 막힘 없이** — 브랜드 등록 → 캠페인 → 이미지 → 편집 → 검수 → 내보내기를 한 번에 완주 | 처음 쓰는 사람 1명이 도움 없이 완주(시연 시나리오 `docs/05` 기준, 10분 이내) |
| 2 | **되돌리고 정리할 수 있음** — 만든 것을 지우고 이름을 바꿀 수 있고, 위험한 동작은 확인을 거친다 | 캠페인·브랜드 삭제, 이름 바꾸기, 위험 동작 분리가 동작 |
| 3 | **돈과 오류가 예측 가능** — 과금 동작은 누르기 전에 비용·남은 횟수가 보이고, 실패는 원인과 다음 행동이 보인다 | 과금 버튼마다 예상 비용 표시, 오류 5종(크레딧·한도·네트워크·입력·서버)에 안내 |
| 4 | **보여 줄 수 있음** — 배포 링크, README, 스크린샷·시연 영상, 설계 문서가 최신 | README 첫 화면만으로 무엇을 하는 서비스인지 이해, 링크 3개(배포·문서·영상) 동작 |

범위 밖(v1.0 이후): 다중 사용자·권한, 결제, 신규 매체 대량 추가, 모바일 전용 화면.

## 3. 진행 방식
- 항목 하나 = 이슈 하나 = 브랜치 하나 (`docs/13` 참고). 이 문서의 표가 원본이고, 이슈는 착수할 때 만든다.
- 한 마일스톤을 끝낼 때마다 develop → main 병합, 태그(`v0.10.0` …), `CHANGELOG.md` 갱신.
- 마일스톤 안에서는 "높음"부터. 새로 발견한 문제는 이 표 맨 아래에 추가하고 우선순위를 매긴다.
- 범위가 부풀면 v1.0 조건 4개를 기준으로 자른다. 조건에 기여하지 않는 항목은 v1.0 이후로 미룬다.

## 7. 계획표 (2026-11-10 ~, 범위 고정)
11/06 방향 전환 뒤 0~5단계와 후속(심사 기준 보강·표본 확대)이 끝났다. 2026-11-09 사용자 판단: 지금 결과물은 이미지·합성, 레이아웃·타이포, 카피, 흐름·화면 모두 실제 광고 시안으로 쓸 수 없는 수준이다 → **피드 세트 생성기로 전면 개편**(아래 B). 사용자와 한 단계씩 합의하며 진행한다.
- 규칙: 이 표에 있는 일만 한다. 작업 중 떠오른 새 아이디어·개선은 아래 '보류'에 한 줄로 적고 손대지 않는다. 표를 바꿀 때는 먼저 이 절을 고치고 나서 착수한다. 한 번에 한 단계, 단계마다 사용자 확인.

### A. 잔여 3건 (개편 전)
| 순서 | 할 일 | 상태 |
|---|---|---|
| A1 | 누끼 잔여물: 업로드 직후 누끼 미리보기(격자 배경) + "원본 그대로 쓰기"(원본 자산 `original_id` 함께 저장) | 구현·테스트(미커밋), 화면 미확인 |
| A2 | 뷰티 매체 RSS 수집(코스인코리아·코스모닝, 제목·첫 문장·링크만) | 구현·테스트(미커밋), 등록 안 함. 트렌드는 새 흐름에서 쓰지 않음 → 코드 처리(되돌리기/남기기) 미정 |
| A3 | 트렌드 효과 재측정 | 취소: 두 번의 측정에서 효과 없음, 새 흐름에서 트렌드 제외(`compare_trend.py` 의 새 기준 변경분은 A2 와 함께 처리) |

### B. 전면 개편: 피드 세트 생성기 (2026-11-09 합의)
**한 문장 정의**: 디자이너 없이 혼자 인스타그램을 운영하는 소상공인 화장품 브랜드가, 제품 사진 한 장으로 가상 모델이 등장하는 피드 이미지 3장(모델이 제품을 든 모습 · 모델이 제품을 사용하는 모습 · 제품 상세)과 긴 글 캡션을 얻는다. 가상 모델은 브랜드마다 저장해 같은 얼굴로 재사용한다.

| 항목 | 결정 |
|---|---|
| 가상 모델 | 브랜드마다 남자·여자 각 1명(후보 중 선택해 저장), 게시물마다 제품에 맞춰 사용자가 고른다 |
| 이미지 위 문구 | 짧은 문구, 장마다 켜고 끄기(기본: 첫 장만) |
| 결과 화면 | 실제 인스타 피드 모양(프로필 줄 · 3장 캐러셀 · 아이콘 줄 · 캡션). 캡션 자리에 긴 글 카피, 그 자리에서 수정 |
| 기존 흐름 | 고치지 않고 얼려 "이전 버전(비교용)"으로 남긴다(아모레 7단계·현재 소상공인 `SmallBizPage`·`routers_smallbiz`). 새 흐름은 새 화면·새 라우터 |
| 캡션 사례 | Claude 가 공개 자료(Meta 광고 라이브러리·브랜드 공식 계정 등)에서 후보 60~80개 정리 → 사용자가 30~50개 선택. 자동 수집(스크래핑) 없음, 구조 참고용 |
| RAG | 규제 층 유지, '사례' 층 신규. 아모레 브랜드·제품 지식과 트렌드는 새 흐름에서 쓰지 않는다 |
| 품질 기준 | ① 제품 그대로(모양·라벨·색) ② 고치지 않고 올릴 수 있음 ③ 화장품법 위반 0건 ④ ChatGPT 에 같은 사진으로 부탁한 결과보다 낫다 |
| 평가 | 제품 사진 10장으로 이전 버전 · 새 흐름 · ChatGPT 3자 블라인드 비교 |

앞선 세 문제의 원인과 해결:
- 배경이 제품과 안 어울림 — 원인: 누끼 합성 방식은 배경을 만들 때 제품명을 "상품(나중에 합성, 그리지 않음)"으로 바꾸고 설명을 빼서, 모델이 제품을 모르는 채 빈 배경을 그린다(`imagegen.build_prompt` composite 분기). 해결: 이미지 모델이 제품 사진과 모델 얼굴을 참조로 받아 장면을 함께 그린다
- 카피가 단조로움 — 원인: 생성 프롬프트가 금지 규칙 위주라 가장 안전한 문장을 쓰고, 입력(제품명·라벨)이 빈약하다. 해결: 생성은 자유롭게·검수는 뒤에서(검수·고쳐 보기 재사용), 이미지 3장의 장면에 맞춘 캡션, 사례를 보여 주고 쓰게 한다
- RAG 가 쓸모없음 — 원인: 아모레 웹 자료는 소상공인과 무관, 트렌드는 효과 없음. 해결: 규제 + 사례 층만
